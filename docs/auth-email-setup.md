# Почта: восстановление пароля и уведомления о входе

Приложение и обработчик готовы, но реальная доставка требует настроенного почтового отправителя. Стандартный тестовый отправитель Supabase может отправлять письма только участникам организации и имеет строгие лимиты; для студентов нужен Custom SMTP.

## Где проверить

1. Открыть https://supabase.com/dashboard/project/mrxqzzaayyaiwyarwqsg/auth/smtp.
2. Проверить, включён ли **Custom SMTP**. Использовать SMTP почтового сервиса с подтверждённым адресом отправителя и достаточным лимитом для входов студентов. Для обычного почтового ящика нужен отдельный пароль приложения, если этого требует провайдер.
3. Пароль SMTP, ключ сервиса и личный Management API token не пересылать в чат и не добавлять в GitHub или клиентский JavaScript.

## Однократная настройка

Разработчик с доступом владельца запускает `python3 scripts/configure_auth_email.py --apply` в доверенном терминале. Скрипт запрашивает секреты скрытым вводом, меняет шаблоны и SMTP в Auth, сохраняет SMTP в секретах Edge Function и только затем включает уведомления о входе. Без `--apply` он лишь показывает план и ничего не меняет.

Потребуются Management API token владельца проекта, SMTP host, порт 465 или 587, пользователь, пароль приложения и подтверждённый адрес отправителя. Разрешены переменные окружения `SUPABASE_ACCESS_TOKEN`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`; файлы `.env` и их значения не публикуются.

Если настраивать вручную, в Auth → Email Templates вставить соответствующие HTML из `supabase/email-templates/`, включить уведомления о смене пароля и почты, указать сайт `https://ariignatenok.github.io/politeshik/` и разрешённый redirect `https://ariignatenok.github.io/politeshik/?recovery=1`. Для ручной настройки также скопировать ключ транспорта из Vault в секрет `LOGIN_DISPATCH_KEY` функции, не раскрывая его в чатах и логах. В Recovery обязательно должен быть `{{ .Token }}`. Код — 6 цифр, срок действия — 600 секунд. После настройки тех же SMTP-секретов у Edge Function включить `politeshik_private.login_mail_settings.enabled` из доверенного SQL Editor.

## Как работает безопасность

- Код и смена пароля проверяются Supabase Auth. До проверки кода новый пароль не отправляется; промежуточная сессия восстановления хранится только в памяти отдельного клиента.
- Ссылка восстановления тоже поддерживается; токены удаляются из адресной строки и не попадают в основную сессию приложения.
- Письмо о входе создаётся по серверной записи Auth с методом `password`, в том числе при входе напрямую через API. Обновление токена и проверка recovery-кода не создают повторных уведомлений.
- Письма отправляет Edge Function с SMTP-секретами на сервере. Запрос доставки подписан одноразовым токеном конкретного события на 90 секунд; в базе хранится только его SHA-256. Содержимое HTTP-очереди дополнительно зашифровано AES-CBC и подписано HMAC-SHA-256 отдельными производными ключами. Ключ транспорта хранится в Supabase Vault и секретах Edge Function, в браузер не передаётся. RPC доставки доступны только `service_role`.
- Доставка изначально выключена. Сбой SMTP не блокирует вход. Повторы ограничены тремя попытками и окном 15 минут, чтобы после настройки не отправить студентам старые письма. SMTP не гарантирует абсолютное отсутствие повторной доставки при сетевом обрыве после принятия письма; Message-ID для одного события остаётся одинаковым.

## Проверка после подключения

На собственном аккаунте запросить один recovery-код, проверить ошибочный код, затем правильный код и новый пароль. Войти новым паролем в отдельном браузере: должно прийти письмо о входе. Проверить письмо о смене пароля и папку «Спам». Убедиться, что профиль и роли не изменились. Не проверять рассылкой на все аккаунты.

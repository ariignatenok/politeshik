# Политешик — учебный планировщик групп 25290909/3091 и 26290911/3111

Веб-приложение без сборки: HTML, CSS и JavaScript плюс Supabase (вход и база данных).

## Две изолированные группы

- `group_1`: 25290909/3091, прежние аккаунты и данные сохраняются.
- `group_2`: 26290911/3111, отдельный список из 26 фамилий, код регистрации, каталог предметов и преподавателей.
- Выбор группы и фамилии происходит после регистрации/подтверждения личного email через Supabase Auth.
  Кабинет создаётся одной серверной операцией `register_student`: проверяются группа, её код, фамилия,
  подгруппа и дополнительный пароль для защищённых ролей. Обычные студенты ждут одобрения старостой.
- Лебедев Петр Андреевич получает роль старосты только своей группы; Кузьменков Макар Сергеевич —
  разработчика с просмотром журнала, пользователей и диагностики, без записи посещаемости и управления доступами.
  У студентов второй группы посещаемость доступна только для чтения.
- Супер-администратор определяется закрытой серверной таблицей по существующему аккаунту Арины,
  а не по введённой фамилии или метаданным браузера. Только ему доступны «Доступы» и переключение групп.
- Все таблицы с `tenant_id` защищены дополнительным ограничивающим RLS-правилом. Административные RPC
  проверяют принадлежность целевого аккаунта группе. Запросы приложения и кэш также разделены по группе.
  Заголовок выбора группы принимается только от проверенного супер-администратора; обычные аккаунты
  не могут изменить свою группу заголовком, JWT-метаданными или редактированием JavaScript.
- Для новой группы есть три отдельные переписки: староста, разработчик и «Админ Арина».
  Автор сообщения подписывается на сервере. Супер-администратор видит переписки выбранной группы.
- Дополнительные пароли ролей хранятся в закрытой схеме только как bcrypt-хеши. Они передаются владельцу
  отдельно и не входят в репозиторий. Личные email и пароли сотрудники задают самостоятельно.

Изменения базы находятся в `supabase/migrations/` и уже применены к проекту. Старые SQL-установщики
предназначены для исходной установки: повторный запуск поверх многогрупповой версии блокируется,
чтобы не заменить её правила доступа старыми. Для обновлений используйте новые миграции.

Проверки: `node --test tests/*.test.cjs`, `python3 -m unittest discover -s tests -v`.
`tests/multigroup-rls.sql` проверяет роли и прямые запросы к базе внутри транзакции с итоговым `ROLLBACK`;
созданные для теста аккаунты и данные не сохраняются.
`tests/welcome-registration.sql` проверяет однократное приветствие Арины после создания кабинета
в группе 26290911/3111, отсутствие рассылки первой группе и приватность чата (также с `ROLLBACK`).

После создания кабинета обычному студенту группы 26290911/3111 один раз приходит приветствие
в личный чат с «Админ Арина». Староста, разработчик и первая группа исключены.
В «Чатах» Арины для второй группы показаны получатели, отправка и отметка прочтения;
серверный отчёт недоступен остальным ролям. Уже зарегистрированные студенты включены без повторной отправки.

## Автоматическое расписание ИСПО

Для обеих групп расписание загружается из `https://polytech-schedule.ru/api/schedule/range`
с отдельным параметром `group`. Файлы: `data/schedule.json` и `data/schedule-26290911-3111.json`.
GitHub Actions (`.github/workflows/sync-schedule.yml`) проверяет источник каждые 15 минут;
GitHub может запускать задания с задержкой. Задание также запускается при изменении скрипта
и вручную через Actions → Sync Polytech schedule → Run workflow. Секреты Supabase не нужны.
Для записи файлов `data/` заданию требуется разрешение `contents: write`;
политики организации и защиты main должны разрешать эту запись.

Открытое приложение получает опубликованный JSON при запуске, возврате на страницу и каждые
5 минут. JSON читается из основной ветки через raw.githubusercontent.com, поэтому обновление
данных не зависит от повторной сборки GitHub Pages. Локальная копия и service worker сохраняют
расписание без сети. Плашка показывает источник и дату снимка; при ошибке остаются последние данные.

Подгруппы, аудитории, преподаватели, замены, отмены и примечания сохраняются отдельно для каждой пары.
Отменённые пары исключаются из расчётов посещаемости соответствующей подгруппы. Сокращённые
названия сопоставляются с существующими предметами, чтобы сохранить связи с ДЗ и конспектами.
Ручное редактирование доступно старосте, как и до подключения ИСПО. Исправление, перенос, добавление
или удаление закрепляет соответствующие ячейки дня и номера пары: автозагрузка их не перезаписывает,
остальные ячейки обновляются из ИСПО. Правки хранятся в общем документе расписания и передаются другим
устройствам и участникам. «Вернуть автообновление недели» убирает ручные правки выбранной недели.
Ручной импорт или копирование закрепляет всю заменённую неделю. Недели вне опубликованного
диапазона продолжают использовать сохранённое расписание; отсутствие ещё не опубликованной недели
не считается отменой всех занятий. Время звонков источник в API не отдаёт — оно остаётся в настройках приложения.

Скрипт запрашивает предыдущую неделю и пять недель вперёд, сохраняет до 40 недель истории,
записывает только полностью проверенный ответ. При изменениях или первом успешном обновлении за день
создаётся коммит со свежим снимком. Если источник сменит формат API, задание завершится ошибкой,
сохранив прежние данные. Новый формат нужно проверить и обновить в скрипте.

Проверки: `python3 -m unittest discover -s tests -v` и `node --test tests/schedule-sync.test.cjs`.

## Что умеет

- Расписание, посещаемость (П, О, Н), журнал, лимит пропусков, рейтинг группы, достижения.
- ДЗ и работы со сроками (напоминания без отметок «выполнено»).
- Конспекты с файлами (PDF и фото), карточки, формулы.
- Чаты: у студента два (Политешик и админ), у админа список студентов с закреплением.
- Новости с комментариями.
- Для админа: вкладка «Больничные» (справки, фото, подтверждение, удаление), редактор посещаемости, данные одинаковы на всех её устройствах.
- Политешик меняет наряд по датам (осень, зима, 14 и 23 февраля, 8 Марта), дышит, моргает, прыгает и машет по клику.
- Стекло в шапке и окнах, появление карточек, скелетоны загрузки, тонкий скроллбар.
- Вход преподавателя (пароль проверяет сервер): расписание, журнал только для чтения, новости, чат с админом.
- Умные больничные: Политешик перечисляет пропущенные пары. Поиск Cmd+K, кнопка «+», экспорт дедлайнов в календарь (.ics), свайпы в расписании.
- Дни рождения (дата в профиле, поздравление Политешика, пост в новостях, лайки), поддержка Политешика (настроение, обнимашки, мотивация), конфетти.
- Расписание по неделям (у каждой недели свои пары, стрелки между неделями), защита от падений разделов, строгий макет без дёрганья, психологическая помощь Политешика.
- ВАЖНО при обновлении: заливайте ВСЕ файлы из архива сразу (js, css, index.html, service-worker.js). После сборки на файлах стоит метка версии, частичная заливка даёт красную плашку со списком недостающих файлов.
- Мой Политешик: аксессуары (очки, сережки, шляпка, бабочка, беретик, реснички) и эмоция дня в личном кабинете; тема Clean Girl.
- Карта колледжа (5 этажей, «Я здесь»), вкладка «Готовое ДЗ» у предметов, записка на отдельные пары, фокус-режим с таймером на 25 минут.
- Темы: светлая, тёмная, Барби, Океан, Космос, Сад, Магия и сезонные (осень, зима, 14 и 23 февраля, 8 Марта; появляются в меню только в свои даты).

Скрипты подключаются обычными тегами `<script>` и делят общую область видимости, поэтому порядок в index.html важен.

## Правила кода

- Комментарии только в виде JSDoc у функций; в коде нет эмодзи (они в `js/icons.js`).
- Права защищены на сервере (RLS в `sql/politeshik.sql`), а не в браузере.

## Установка на телефон (PWA)

- iPhone: откройте сайт в Safari, нажмите «Поделиться», затем «На экран Домой». Push-уведомления на iOS работают только у приложения, добавленного на экран Домой (iOS 16.4 и новее).
- Android: Chrome предложит «Установить приложение» сам, либо меню, затем «Установить приложение».
- После обновления файлов на GitHub поменяйте `CACHE_VERSION` в `service-worker.js` (например, `v2`), чтобы старые копии в телефонах заменились.
- Иконки лежат в `assets/` (`icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon.png`): можно заменить своими с теми же именами и размерами.

## Установка на GitHub и Supabase

1. **GitHub.** Скопируйте содержимое папки в репозиторий `ariignatenok/politeshik` (GitHub Desktop: Commit, затем Push; через сайт: Add file, Upload files). Через 1-2 минуты обновите сайт (Cmd+Shift+R).
2. **Supabase.** Откройте `sql/politeshik.sql`, в первой строке замените `ПРИДУМАЙТЕ_СЕКРЕТНЫЙ_ПАРОЛЬ` на свой секретный пароль (прежний останется прежним). Вставьте весь файл в SQL Editor и нажмите Run. Скрипт можно запускать повторно.

## Вход админа

Регистрация со своей почты, выбор «ИГНАТЕНОК Арина», секретный пароль. Секретный пароль проверяет сервер.
